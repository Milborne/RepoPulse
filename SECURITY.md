# Security Policy

## Supported Versions

RepoPulse supports the latest published major version, currently `v1`.

## Reporting a Vulnerability

Please do not open public issues for security vulnerabilities.

The recommended reporting channel is GitHub Private Vulnerability Reporting for this repository. Do not share sensitive details until that private channel is available.

If GitHub Private Vulnerability Reporting is not enabled yet, ask the maintainer to enable it before sending exploit details, proof-of-concept code, private logs, or information about affected users. Maintainers should enable GitHub Private Vulnerability Reporting before publishing a stable Marketplace release.

Include:

- a clear description of the issue;
- steps to reproduce the behavior;
- the expected impact;
- affected versions or tags;
- any suggested mitigation.

Maintainers should acknowledge reports within 7 days and share a remediation plan when the issue is confirmed.

## Scope

RepoPulse runs local repository checks and does not intentionally call external services. Security reports should focus on action execution, unsafe filesystem behavior, dependency risks, or incorrect handling of untrusted repository content.
